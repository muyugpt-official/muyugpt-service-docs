## 二、MuyuGPT 通用订单流程

不同 AI 产品和不同商品可能采用不同的实际交付方式。

通用流程可以概括为：

**选择产品 → 阅读套餐与交付说明 → 创建订单 → 完成付款 → 查询订单状态 → 按订单说明完成后续步骤 → 用户本人验收结果**

下单前建议至少确认：

1. 产品名称；
2. 套餐名称；
3. 使用周期；
4. 当前人民币价格；
5. 付款方式；
6. 交付方式；
7. 用户是否需要完成额外操作；
8. 到账或验收方式；
9. 售后与退款边界。

实际信息始终以对应产品页和订单页面实时显示为准。

## 三、付款状态和服务状态不是一回事

数字服务中需要区分两个概念：

### 付款状态

用于说明订单资金是否已经确认。

常见情况可能包括：

- 待支付；
- 已支付；
- 支付失败；
- 退款处理中；
- 已退款。

### 服务处理状态

用于说明付款后的服务流程进行到哪一步。

常见情况可能包括：

- 待处理；
- 已进入处理流程；
- 处理中；
- 等待用户操作；
- 已完成；
- 处理异常；
- 售后处理中。

因此：

> **付款成功不一定代表整个服务已经完成。**

如果订单已经付款但仍然显示处理中，请先查询订单状态，不要重复创建相同订单或重复付款。

## 五、不同商品可能采用不同交付方式

MuyuGPT 不使用一种固定交付方式描述所有 AI 产品。

不同商品可能采用：

### 本人账号相关方案

服务结果与用户自己的 AI 产品账号相关。

如果需要登录或确认账号，应尽量由用户本人进入对应 AI 产品官方页面完成。

### 自助或兑换流程

部分商品可能需要用户根据订单页面提供的说明自行完成后续步骤。

### 独享账号 / 成品号

部分商品可能交付一个独立使用的账号。

购买前需要重点确认：

- 使用周期；
- 是否独享；
- 是否允许修改资料；
- 账号使用规则；
- 质保期限；
- 售后范围。

### 其他交付方式

如果商品采用其他处理方式，应以对应商品页面和订单页面的实际说明为准。

不要根据旧文章或其他商品的流程推断当前订单。

## 六、订单查询

付款完成后建议保存订单信息。

查询订单时可能需要：

- 订单编号；
- 下单联系方式；
- 页面要求的其他查询信息。

订单查询的主要目的包括：

- 确认付款状态；
- 查看服务处理进度；
- 查看是否需要用户操作；
- 获取与本次订单对应的交付说明；
- 查看最近更新时间；
- 判断是否已经进入售后流程。

如果状态暂时没有变化，不建议连续重复提交订单。

## 七、账号安全原则

第三方 AI 订阅协助不应该把高权限账号凭证当作普通订单信息。

请不要向陌生人提交：

- AI 产品账号密码；
- 邮箱密码；
- 短信验证码；
- 邮箱验证码；
- Cookie；
- Session Token；
- Authorization 信息；
- API Key；
- 两步验证恢复代码；
- 其他可以直接获得账号控制权限的凭证。

尤其需要注意：

**Cookie、Session Token 和 API Key 并不是普通文本。**

部分会话凭证可能代表已经完成登录的账号访问权限。

如果某个操作要求用户：

**打开浏览器开发者工具 → 查找 Cookie / Session → 复制 Token → 发送给第三方**

应该先停止操作，并确认：

- 为什么需要这项数据？
- 它会授予什么权限？
- 是否存在用户本人操作的替代方案？

## 八、需要登录账号时怎么办？

更合理的处理原则是：

**用户本人进入对应 AI 产品官方页面 → 用户本人登录 → 用户本人完成必要操作 → 用户本人检查最终状态**

第三方订单系统主要负责：

- 订单信息；
- 服务处理；
- 状态查询；
- 必要说明；
- 自身服务范围内的售后处理。

账号控制权应尽量保留在用户本人手中。

## 九、订单完成后如何验收？

订单页面显示“完成”以后，建议用户本人继续确认实际产品状态。

重点检查：

1. 当前登录的账号是否正确；
2. 实际套餐是否符合订单；
3. 使用周期是否符合说明；
4. 所需会员功能是否已经出现；
5. 商品类型是否与下单时一致；
6. 是否误把网页会员与 API 服务混为一谈。

最终 AI 产品状态，应优先以对应产品官方账号页面显示的信息为准。

## 十、遇到订单异常怎么办？

如果订单没有按照预期完成，建议按以下顺序排查。

### 1. 不要重复付款

先确认原订单是否已经完成付款。

### 2. 查询订单状态

查看当前属于：

- 待支付；
- 已支付；
- 处理中；
- 等待用户操作；
- 已完成；
- 处理异常；
- 售后处理中。

### 3. 核对商品

确认：

- 产品；
- 套餐；
- 周期；
- 交付方式；
- 下单账号或相关信息。

### 4. 阅读当前订单说明

旧教程不能替代本次订单页面显示的实际信息。

### 5. 保留订单资料

包括：

- 订单号；
- 支付记录；
- 页面提示；
- 必要的问题截图。

不要在公开页面发布含有个人信息或敏感凭证的截图。

## 十一、退款与售后边界

不同商品可能具有不同的：

- 交付方式；
- 处理时间；
- 售后条件；
- 退款条件；
- 质保范围。

因此，不能用一个固定退款规则概括全部商品。

判断具体订单时，应优先查看：

1. 下单时对应的商品说明；
2. 订单页面；
3. 当前售后规则；
4. 实际订单状态。

如果订单已经进入处理或完成交付，实际售后范围可能与尚未处理的订单不同。

具体规则以用户下单时和当前订单页面实际显示的信息为准。
